## Workflow that worked
- One branch per milestone step (`feat/…`), atomic Conventional Commits, a `docs:` commit for README/ROADMAP/ARCHITECTURE/ADR.
- Before every PR, run `code-reviewer` and `security-auditor` in parallel on `git diff <base>...HEAD`, fix the findings in `fix(...)` commits, and have the auditor re-check any High fix.

## Checks
```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check
cargo xtask tokens --check
```
A local hook refuses `git commit` when fmt or clippy fail on the touched crate: run them first. The hook checks before the command runs, so a combined "fix && commit" command is refused as a whole.

## Traps already hit
- **Formatter hook in xtask**: the post-edit formatter hook can rewrite `xtask/src/*.rs` imports in an older rustfmt style; run `cargo fmt --all` and revert files you did not mean to touch before committing.
- **Pictures** (ADR-0021): check dimensions from the header before any decoder allocates, oxipng included (it inflates to the size the IHDR announces and aborts the process on failure); hold the processing permit inside `spawn_blocking`, since a timeout does not stop the work; `image` does not apply EXIF orientation by itself; real-world GIFs are often truncated (browsers show the frames read), and the frame iterator then yields errors forever.
- **Enum size**: adding fields to `PublicUser` pushed `GatewayEvent` over clippy's `large_enum_variant`; `ServerFrame::Dispatch` boxes its event (wire format unchanged).
- **SQLCipher**: every pool must be closed (`pool.close().await`) before the process or test ends, or the process crashes at exit (ADR-0006). Integration tests stop the server and await it.
- **Nonces in tests**: a repeated nonce returns the first message, so fixtures sending several messages need a distinct nonce each (see `post_message` in the gateway tests).
- **Clock in tests**: the gateway validates sessions against the real clock; fixtures that log in through the gateway must use real time, not the fixed `NOW`.
- **Integration tests of the client core** run a real server through `initialize_instance` + `serve_instance` on a probed free port (`crates/mellow-client-core/tests/`).
- **Desktop modes**: without environment variables the app resumes the session stored in the OS secret store, or shows the sign-in screen; sign out from the gear menu of the user panel to get back to it. On macOS an unsigned build changes identity on every rebuild, so Keychain asks again for access to the stored entry. `MELLOW_DEMO_WORKSPACE=1` (also implied by the scroll benchmark and `MELLOW_SPIKE_SNAPSHOT_DIRECTORY`) runs the fake-data shell. Snapshots are written by the app itself, because screen capture is not permitted.
- **Desktop sessions**: results of network calls are dropped when `session_generation` changed since they started (sign out, sign in again, server rejection), so a late 401 of the previous session cannot end or forget the new one. Use `run_request` for every call, and check the generation in any new UI-thread loop. Secret store calls are serialized by a mutex in `session_store` and bounded by `SECRET_STORE_TIMEOUT` (10 s); release builds never store or resume a session on a loopback (plain http) instance. Known limit: if the secret store can neither be read at launch nor written after sign-in, an older stored session stays there, valid, until a later launch resumes it.
- **Slint popups**: `PopupWindow::close()` destroys the popup's content, so any statement after it in a handler inside the popup never runs. Call the action first, then `close()` (the server menu shipped broken in `v0.7.0` this way). `src/server_menu_tests.rs` drives the real window with `i-slint-backend-testing` (dev-dependency; debug builds emit Slint debug info so elements are found by accessible label): pointer clicks at rendered positions, popup items reported relative to the popup.
- **Slint repeaters**: `VecModel::set_vec` resets the model, which recreates every row instance. Any state typed into a row (the inline message editor's draft) must live above the repeater (`editing-message-draft` on `ChatPane`), and rows are addressed by index only through `displayed_message_ids`, remapped after each rebuild (`live_shell/message_actions.rs`).
- **StyledText in layouts**: a `StyledText` inside a `HorizontalLayout` loses its height-for-width, so wrapped messages overlap the next row. Keep it a direct child of the message's `VerticalLayout`; check long messages in a snapshot after any change around it.
- **Snapshots of UI states**: hover and dialogs cannot be captured directly. Temporarily set the window properties (`set_editing_message_index`, `set_deleting_message_index`, …) in `window_snapshot::schedule`, capture with `MELLOW_SPIKE_SNAPSHOT_DIRECTORY`, then revert the file.
- **Outbox rows**: pending and failed messages are extra rows after the confirmed ones; a row index at or past `displayed_message_ids.len()` maps into `displayed_pending_nonces`. They carry `is_own = false`, so no message action ever targets them.
- **Outbox resend**: after `Ready` and `Resumed`, failed messages go out one after another (`resend_failed_messages`, each step through `run_request`), so they keep their order among themselves; sending them in parallel could reorder them. Messages still `Sending` are never part of a batch.
- **Message list scrolling**: `refresh_messages` never scrolls. The Slint list stays pinned at `pinned-distance-from-latest-message` from the bottom (zero by default; set by `keep-distance-from-latest-message` before older rows are prepended); only a user scroll (`scrolled`) re-decides pinning. `scrolled` alone misses flicks that coast to the top, so the older-history check also runs on `content-y` and `content-height` changes. Opening a channel and sending call `scroll_to_latest_message_after_layout` / `invoke_scroll_to_latest_message` explicitly.
- **Row 0 height in the message list**: never pin the list at a distance (`keep-distance-from-latest-message`) while row 0 is on screen and changing height. Slint 1.18's ListView estimates its content height from the visible rows, and the estimate and the pinned position then chase each other every frame ("long callback/instantiation chain detected" warnings). The history-start block above row 0 compensates its own height changes (`keep-rows-in-place-after-history-start-change`), and an empty older page skips the pin.
- **Jump to present**: the bar follows `is-viewing-older-messages`, not `is-pinned-to-latest-message`, because `keep-distance-from-latest-message` pins the list far from the bottom while older pages are prepended. `scrolled` reads the position a wheel or flick animation starts from (Slint 1.18 `Flickable`), so a scroll coasting to the bottom is released there and pinned again by `pin-when-latest-message-reached` on `content-y`, `content-height` and `visible-height` changes, at distance zero only. Rust calls `note-new-message` for each `MessageCreate` from someone else in the open channel.
- **History failures**: a failed history request puts the channel in `failed_history_channel_ids`, which stops the automatic older-history loads on scroll. Only "Try again" (`retry_loading_history`), reopening the channel or the next `Ready` clears it.
- **History pages**: always request `limit: HISTORY_PAGE_SIZE`, since `insert_history_page` reads a shorter page as the channel's start. An older page is inserted only if the channel's oldest cached message is still its `before` cursor, so the cache never has a gap.
- **Channel permissions in the UI**: `ClientState::my_channel_permissions` only adapts the interface. The server refuses edits as well as sends without `SEND_MESSAGES` (a muted member cannot republish by editing), so the desktop hides Edit with Reply in a read-only channel. On `StateChange::Guilds` the message rows are rebuilt only when `MANAGE_MESSAGES` changed (`displayed_can_manage_messages`): rebuilding recreates an open inline editor, which takes the focus and moves its cursor.
- **Server text in the UI**: never show `ClientError::Api`'s `message` in a trusted place; build the text from `ApiErrorCode` (see `message_action_error_text`).
- **Desktop threading**: state lives on the UI thread in `Rc<RefCell<LiveShell>>`. Network futures run on the tokio runtime and come back through `slint::spawn_local`. Never hold a `RefCell` borrow across a call that borrows again.
- **Svelte `{@const}` in dialog callbacks**: a `{@const message = deletingMessage}` follows its state, so a callback that clears the state and then reads the const gets `null` (the confirmation dialogs in `ChatPane.svelte` sent nothing until #80). Read the value into a local first, then clear the state.
- **Testing message actions in a browser**: Shift+click on Delete skips the confirmation dialog, so a check that uses it misses the dialog path; confirm through the dialog with real clicks too. The action bar exists only on a hovered or focused row (and the row holding the Tab stop), and is `visibility: hidden` until then, so a hidden button cannot take focus. Local check: an instance in the scratchpad (`init --listen-address 127.0.0.1:18080 --registration-mode open`) plus `npx vite` in `web/`, which proxies to it.
- **Web message Markdown** (`web/src/components/markdown.ts`): closers are searched once per kind and the answer is reused by later openers, which only works because each closer test ignores where its opener is; keep it that way when adding a construct, or 4 000 `*` turn quadratic (a test guards it). Svelte keeps template whitespace inside `whitespace-pre-wrap` paragraphs, so inline nodes are written without whitespace between tags.
- **Message markdown**: escape `\` before `<`, or `\<font>` re-enables HTML styling (fixed, with a regression test).
- **TLS listener**: hyper ignores its header timeout unless a timer is set. Do not enable HTTP/2 keep-alive pings, since their answers keep idle connections alive. `axum-server`'s `http1_only()` breaks WebSocket upgrades.
- **ACME**: tests point at an unreachable directory URL (`https://127.0.0.1:9/directory`), so they never touch Let's Encrypt. The end-to-end test against Pebble is `#[ignore]`d: download a release binary from github.com/letsencrypt/pebble, `chmod +x` it (the archive drops the executable bit), then `MELLOW_PEBBLE_BINARY=/path/to/pebble cargo test -p mellow-server --lib tls::tests -- --ignored`. It sets `PEBBLE_WFE_NONCEREJECT=0` because rustls-acme does not retry a bad-nonce refusal.
- **Reverse proxy in Docker**: the proxy reaches Mellow from its container address, not loopback, so `X-Forwarded-For` is ignored unless that address is in `trusted_proxy_networks`. Trust the proxy's `/32`, never the whole Docker network (its gateway is the host and the userland proxy's source).
- **Rate limiter tables**: `AppState` holds three `RateLimiter`s, each capped at 100 000 live keys (a full table refuses every new key). `rate_limiter` takes only keys of signed-in requests (user, channel, or the address of a request with a valid session, such as `invite:`); `unauthenticated_rate_limiter` takes keys counted before any session (`authentication:`, `login:`); `gateway_rate_limiter` takes `gateway:{address}` alone, so a sign-in flood cannot stop signed-in users from reconnecting. A new limit goes in the table of who can create its keys. Login records its per-account keys only when the address limit allowed the attempt.
- **Password-dependent writes**: a write that relies on a verified password (new session, password change) is conditional on the stored hash still being the verified one (`insert_session`, `replace_password_and_delete_other_sessions`), and current-password checks are rate limited per session (`password-check:` keys), never only per user, so a stolen session cannot lock the owner out of revoking it. A new username needs the current password.
- **Role checks**: every role action goes through `RoleManager::can_manage_role` (rank and permission subset); `add_member_role` repeats the subset check in its SQL and `update_role_fields` writes only the bits the actor holds, so a permission granted meanwhile is neither handed out nor erased. Never add a role action that skips them.
- **Live instance check**: `crates/mellow-client-core/examples/live_instance_check.rs` (untracked, never commit it) drives a real instance; the user's instance has closed registration, so its test account was made with `admin create-user` through `docker exec` (credentials never in the repository).
- **Audit log**: every moderation or administration write takes a `NewAuditEntry` (`Guilds::audit_entry`) and records it in its own transaction, only when something changed (compare with the stored values first, and fill `changes`). `Guilds::audit_entry` derives the entry's `channel_id` from the action, which hides it from readers who cannot view that channel: a new channel-scoped action must be added there. Leaving a guild or deleting one's own message records nothing.
- **User's instance**: a Docker stack behind Caddy on the user's own machine (host and path in Claude's local memory, never in the repository). Update with `git archive main` into `source/` (the previous one kept as `source.previous`), then `docker compose build && docker compose up -d`; the server backs the database up before migrating. Ask before each update.
- **Reactions in messages**: `Message.reactions` carries `me`, which differs per viewer, so it is filled only in REST answers (`fill_reactions`, `messages_for_viewer`) and stays empty in every gateway event; clients keep their cached reactions when they apply a `MESSAGE_UPDATE`. A new permission bit must also get a row in the desktop role editor (`role_settings::PERMISSION_DESCRIPTIONS`, tested to cover every bit) and, for existing guilds, a migration granting it to `@everyone` if new guilds get it by default.
- **Popovers and their buttons**: a press on the button of an open `popover="auto"` first light-dismisses it, so a plain toggle in `onclick` reopens it at once; remember the open state at `pointerdown` with `createPopoverToggle` (`web/src/components/popover-toggle.ts`). When it closes by light dismiss, put focus back on the button only if focus was inside or on `body`: a click elsewhere gave focus somewhere on purpose. A control under `invisible` (the hover bar) cannot take focus: keep the bar `visible` while its picker or menu is open (`heldMessageId`), so focus can go back to the button.
- **Picking a file in headless Chrome**: `DOM.setFileInputFiles` on the hidden `<input type="file">` fires `change` like a real pick, so the icon editor and the crop dialog can be driven without a file chooser. Svelte attaches `onwheel` to the element itself, not passive, so `preventDefault()` there stops the dialog from scrolling (only `ontouchstart` and `ontouchmove` are passive). Several codes in one `svelte-ignore` comment are separated by commas, or only the first is honoured.
- **Screenshots in a language**: `--lang` does not change `navigator.languages` in headless Chrome on macOS; set `acceptLanguage` with `Network.setUserAgentOverride` before navigating.
- **Channel visibility**: every message or typing event goes through `MessageAudience` and `publish` in `domain/messages.rs` (guild channels: `Guilds::channel_audience`; conversations: their participants only), never `EventHub::publish_to_guild` directly, and every permission change that can hide or reveal channels calls `Guilds::resynchronize` (ADR-0015). A hidden channel answers `NOT_FOUND`, like a missing one.
- **Release assets**: the updaters and the Docker build rely on the names `<binary>-<version>-<target>[.exe]` and on the trusted comment being exactly that name; never change one without the others (`release.yml`, `mellow-update`, `deploy/docker/Dockerfile`). Linux builds run on Ubuntu 22.04 for glibc 2.35: a build on a newer glibc needs `GLIBC_2.38` and refuses to start on Debian 12. No build cache in `release.yml`: a tag run can restore caches written on `main`.
- **Updater install location**: `install_executable` refuses a symlink or an executable or directory writable by group or others or owned by another user, so tests create a 0700 temporary directory first.
- **`init` on the Docker instance**: run it with plain `docker run --user 1000:1000 -v …:/config -v …:/keys …`; `docker compose run -v` keeps the compose file's `:ro`, so `init` cannot write the key.
- **Commit hook**: it checks the branch before the command runs, so `git switch -c … && git commit …` in one command is refused on `main`; switch first.
- **Logs**: never log serde or ACME error text verbatim. Serde quotes the offending value (possibly message content), and the certificate authority's messages can quote the contact email.
- **Licences**: `webpki-roots` and `webpki-root-certs` need the CDLA-Permissive-2.0 exception in `deny.toml`.
- **Clippy pedantic**: `too_many_lines` (100) shows up on large `match` reducers and connection loops; extract a helper rather than allowing the lint.
- **Server settings drafts**: the role draft lives in Rust (`live_shell/server_settings.rs`, `RoleEditor::draft`), `None` while nothing is edited; `refresh` drops it once it equals the stored role, so REST answers are applied at once as a synthetic `GuildRolesUpdate` and the bar disappears. Slint refuses to leave or switch roles while `has-unsaved-role-changes`; Rust still checks `is_busy` and the role locks (`role_settings::RoleManager` mirrors the server's `can_manage_role`, for the interface only).
- **Direct messages**: a conversation is a guild-less channel; guild code finds channels only through `find_guild_channel` (`guild_id IS NOT NULL`), so a conversation id answers `NOT_FOUND` there. Write access is decided per action by `direct_message_permissions(is_participant, shares_a_guild)`. `Ready` lists only conversations with a message; the client keeps an empty one across `Ready` while it holds an unsent message.
- **Web client**: `cd web && npm ci`, `npm run dev` proxies to an instance on 127.0.0.1:18080. `cargo build -p mellow-server --features web-client` embeds `web/dist` (build it first); then the instance serves the client at `/`. When the Claude-in-Chrome extension is not connected, a headless Chrome driven over CDP (a small Node script with the global WebSocket) is enough to sign up, send and screenshot. Chrome serialises computed durations as `.3s`.
- **Nested dialogs in headless tests**: clicks made by `element.click()` from `Runtime.evaluate` carry no user activation, so Chrome groups the dialogs they open and one Esc closes the whole group, the settings included, ignoring `preventDefault` on `cancel`. Pass `userGesture: true` to `Runtime.evaluate` (real clicks and keys are not affected). The scratchpad is shared with other agents: use your own instance directory and port.
- **Settings edits on the web** come from the gateway, never from the REST answer (a late answer would put older state back); pages keep the saved value until the echo arrives. Only removals and a created role are applied from the answer. Unsaved changes are keyed by section (`mustStayOnPage`), so a page that disappears with its permission never traps the reader.
- **Role drafts on the web**: `rebaseRoleEdit` sets the toggled bits to the wanted value instead of flipping them, so the gateway echo of our own save ends the edit; flipping (XOR) would revert it. The desktop's `RoleEdit::rebased_on` flips: check it when the desktop catches up.
- **Web strings**: every visible or announced string lives in `web/src/i18n/en.ts` and `fr.ts` (French typography through the `NO_BREAK_SPACE` / `NARROW_NO_BREAK_SPACE` constants). Server error text is never shown: `describeError` maps codes to `strings.errors.reasons`. Tests run in English whatever the machine's language, because `src/test-setup.ts` stubs `navigator.languages` before `i18n` is imported. Headless Chrome shows French with `--lang=fr-FR --accept-lang=fr-FR,fr`.
- **Comparing with the Dusk mockup**: hide `.mock-bar` and set `.app` to `100dvh` before a screenshot, then measure boxes with `getBoundingClientRect` on both pages. The mockup's empty grid tracks add a second inset above the cards and after the last one; its narrow layout hides the topic without a spacer, so its member button sits next to the title (the web client keeps it at the trailing edge).
- **Web sessions**: the cookie is `__Host-mellow_session` and counts only when `Origin` is `https://` + `Host` (`http://` on loopback); the Vite proxy rewrites its own pages' Origin to the instance. Never add a CORS layer: it would undo the login-CSRF guard (`X-Mellow-Session-Transport`).
- **Passwords in clients**: wipe them once sent — build the request inside the async block and `zeroize()` its password fields after `await` (sign-in, username change, password change). A `Zeroizing` wrapper copied into a plain `String` request protects nothing.
- **Merging needs the user**: the auto-mode classifier refuses `gh pr merge` until the user grants it in the session, even after a "yes" in chat; ask, then retry once granted.
- **Desktop Dusk layout** (`docs/design/desktop-dusk-navigator.md`): compare with the mockup at the same size with `MELLOW_SPIKE_SNAPSHOT_SIZE=1440x900`, `MELLOW_SPIKE_SNAPSHOT_THEME=light` and `MELLOW_SPIKE_SNAPSHOT_STATE=members|drawer|settings` next to `MELLOW_SPIKE_SNAPSHOT_DIRECTORY`; snapshots are in physical pixels (2× on Retina). The mockup's grid adds 16 px at the top and trailing edge; the desktop copies it on purpose.
- **Slint 1.18 limits met**: no `transform-translate` (animate `x`/`y` or an inner element instead); `Flickable.viewport-*` is deprecated (`content-*`); a size computed from the pane's own height (the composer's cap) makes a binding loop through the window's layout, so caps use tokens; an element under `if` cannot be addressed by id from outside it (focus it from its own `init`).
- **Preferences**: theme, reduced motion and the member sheet per server live in `preferences.rs` (a `key=value` file in the OS configuration directory, written off the UI thread). The demo never reads or writes it, so snapshots stay reproducible.
- **Editing files**: rustfmt reformats after each edit. Re-read a file before an exact-match edit if a formatter ran since.
- **Benchmarks and parallel `cargo test`**: a `cargo test` running on the same machine (about 400 % CPU) skewed two of three benchmark rounds of the single-writer measurement. Do not run tests while `performance-optimizer` measures, and check `uptime` before trusting numbers.
- **One writer connection**: a storage function holding a writer transaction must not call another function that writes (it would wait for itself until the 5 s acquire timeout); read helpers after `commit` go to `database.readers()`.
- **Permission snapshot cache**: `Guilds` caches each guild's owner, roles and role assignments and trusts the copy only while `guilds.permission_version` matches (migration 0015 triggers). A new table or column that changes who sees what (a member timeout, say) must bump that version with its own trigger, or fan-out silently uses stale permissions; never write those tables with `REPLACE`, whose implicit deletes fire no trigger.
