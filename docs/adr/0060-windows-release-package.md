# 0060. The Windows release package: a one-screen Inno Setup installer per user

- Status: Accepted (owner's decisions of 2026-11-14, wave 11 of the desktop client)
- Date: 2026-11-14
- Builds on: [ADR-0016](0016-sign-releases-in-a-protected-ci-environment.md) (signed releases), [ADR-0051](0051-gpui-desktop-client.md) (the desktop client), [ADR-0055](0055-desktop-release-packages-and-macos-signing.md) (the desktop packages), [ADR-0056](0056-desktop-keeps-running-in-the-background.md) (running in the background), [ADR-0057](0057-desktop-self-update.md) (the self-update)
- Amends: ADR-0055's "Windows has no package yet" and ADR-0057's "Windows: compiled, and says not supported yet"

## Context
The desktop app builds and passes its tests on Windows (CI since wave 9) but ships only for macOS and Linux. The owner wants a Windows release that a friend can install from the GitHub release page: no store, no account, no administrator rights. In the owner's words, "simple and installs easily", then "beautiful if you can": one screen with an "Install" button, no folder, component or check box to choose, no UAC prompt, Mellow opening by itself at the end, a Start menu entry made without asking, an update or a reinstall that asks nothing, a modern wizard in Mellow's colours with Melli, sharp at high DPI, English or French after the system's language, and no licence to accept.

Also decided with the owner: the signed self-update (ADR-0057, minisign) covers Windows too; there is no code-signing certificate for now, so SmartScreen warns once, at the first launch of the downloaded installer, as macOS's "Open Anyway" does (ADR-0055). A certificate (Certum's open source code signing) and perhaps an MSIX outside the store may come later; the release job must show where signing goes.

Windows forbids writing over a running executable but allows renaming it. Mellow keeps running in the notification area when its window closes (ADR-0056), so an installer run by hand usually meets a running Mellow, and a self-update always does.

The desktop has no URL scheme of its own (invitations are typed or pasted), so nothing has to register a protocol.

## Options
Criteria: per user without administrator rights; a Start menu entry; an entry in Settings, "Installed apps", with a clean uninstall; the icon; how few screens it can show and how good it looks; how it updates a running Mellow; available on the `windows-2025` runner without a doubtful dependency; reproducible; licence.

| | Inno Setup 6.7 | WiX 6 (MSI) | NSIS 3 | Velopack (Squirrel's successor) | Zip, installs itself at first launch |
|---|---|---|---|---|---|
| Per user, no UAC | `PrivilegesRequired=lowest`, `{autopf}` = `%LOCALAPPDATA%\Programs` | per-user MSI possible but fragile (`ALLUSERS=2`, `MSIINSTALLPERUSER`, ICE warnings), and MSI's UI is a separate project | `RequestExecutionLevel user` | yes, `%LOCALAPPDATA%\<app>` | yes |
| Start menu, Installed apps, uninstall | built in | built in | written by hand in the script | built in | to write in the app |
| Screens and look | one welcome page with picture, background colour, light and dark appearance, 100 to 250 % pictures (6.6 and 6.7), French built in | WiX's standard dialogs look like 2005; a modern look means a custom bootstrapper (Burn + WPF) | Modern UI 2 looks dated; a modern look means custom nsDialogs or a plugin | no screen at all: a splash with a progress bar, then the app | none; the app's own window |
| Updating a running app | scriptable: stop or wait for it, then replace | Restart Manager or a reboot prompt | scriptable | its own updater (`Update.exe`), its own delta packages and feed | to write in the app |
| On the runner | not preinstalled on `windows-2025`; one download from its GitHub release, pinned by digest | `dotnet tool`, NuGet packages | Chocolatey or a download | `vpk`, a .NET tool, plus the Velopack crate in the app | nothing |
| Licence | Inno Setup licence (free, also commercially) | MS-RL | zlib | MIT | — |

- **WiX/MSI** gives administrators group-policy deployment, which a friend installing a chat app does not need, and costs a custom bootstrapper for any look beyond the stock dialogs.
- **NSIS** can do everything, but the per-user registration, the uninstaller and any modern look are ours to write and keep up.
- **Velopack** is the simplest for the user (no screen, the app opens) and has a Rust crate, but it brings its own update mechanism (feed, `Update.exe`, delta packages, its own signature model) beside ADR-0057's minisign path, a .NET tool in the release job and a new dependency in the app. Using only its installer and ignoring its updater would leave its updater installed and unused.
- **A zip that installs itself** has no Start menu entry or "Installed apps" entry until the app runs once, and puts install and uninstall logic in the app; SmartScreen warns the same way.
- **Inno Setup** reaches the owner's flow with directives alone: the welcome page is the only page shown, its button reads "Install", the progress bar follows, Mellow opens and the installer closes. Its 6.6 and 6.7 releases added dark mode and background colours, so the wizard matches the Dusk tokens in both appearances.

## Decision
- **Inno Setup 6.7.4**, script `crates/mellow-desktop/packaging/windows/mellow.iss`. The release job downloads Inno Setup's installer from its GitHub release and refuses it unless its SHA-256 is the pinned one (GitHub's own digest of that asset); updating Inno Setup changes the URL and the digest together.
- **One screen.** `DisableWelcomePage=no`, every other page off (`DisableDirPage`, `DisableProgramGroupPage`, `DisableReadyPage`, `DisableFinishedPage`), the welcome page's button relabelled "Install"; no language dialog (the system's UI language picks English or French, Inno Setup's own French messages plus ours); no licence page (the AGPL asks for no acceptance; `LICENSE.txt` is installed beside the app). After the progress bar, `[Run]` opens Mellow (`nowait`) and the installer closes. Silent runs (`/VERYSILENT`) open nothing unless given `/LAUNCH`.
- **Look.** `WizardStyle=modern dynamic hidebevels`: light or dark after the system, background `color.surface.chat` of each theme. The welcome page's picture is Melli under the dusk sky of the favicon (`color.mascot.*`), with a few stars and the apricot glow, rendered at Inno Setup's seven sizes from 100 % to 250 % (202 × 386 to 534 × 1022); the progress page's corner shows the favicon tile at its seven sizes. Everything is generated from `design/tokens.json` and the favicon by `cargo xtask windows-package` when the release job lays out the installer's folder, never drawn by hand; `generated.iss` passes the version, the colours and the picture lists to the script. The installer's and the app's icon is `packaging/windows/mellow.ico` (PNG entries from 16 to 256 pixels), generated and checked by `cargo xtask tokens` like the other icons. The buttons keep Inno Setup's built-in style: matching the apricot accent needs a VCL style file, left for later.
- **Where it goes.** `%LOCALAPPDATA%\Programs\Mellow\mellow.exe` (Inno Setup's `{autopf}` in per-user mode), uninstaller beside it, `HKCU` uninstall entry with the app's icon and version, a Start menu shortcut in the user's Programs folder carrying the AppUserModelID `org.mellow.desktop` (the identifier GPUI gives the process for its notifications, so taskbar and toasts group together). No desktop shortcut (a check box the owner does not want). Windows 10 1809 or newer, x64 (`x64compatible`, so Windows on Arm runs it emulated).
- **What the uninstall removes**: the program folder, the shortcut, the uninstall entry, the notifications' `AppUserModelId` registry key the app wrote, and `%LOCALAPPDATA%\mellow\updates` (staged updates). It keeps the preferences (`%APPDATA%\Mellow`), the drafts and picture cache (`%LOCALAPPDATA%\mellow`) and the session token in the Credential Manager, as `install.sh --uninstall` does on Linux, so a reinstall finds the account signed in.
- **A running Mellow.** Restart Manager is off (`CloseApplications=no`: it asks first). Before copying, the script stops the Mellow running from the install folder, found by its path through PowerShell (another account's or a development build keeps running; the path reaches PowerShell through an environment variable, never inside the script, so no quote in a user name can change the command): at once for a manual install, after the confirmation for the uninstaller, and after up to 60 seconds of waiting when the app itself started the installer (`/UPDATE`), so it can finish quitting (leaving a call, signing out when asked).
- **`RedirectionGuard=no`.** Inno Setup 6.7 turns on Windows' redirection guard, which makes the process (and what it starts) ignore junctions created by unprivileged users: a defence for installers running elevated. This one never does, and the guard would pass to the Mellow it opens at the end, which would then fail to follow the user's own junctions (a relocated Documents or Downloads folder, for instance). Inno Setup then writes the new `mellow.exe` in place; the app's single-instance pipe (ADR-0056) makes the reopened Mellow the only one.
- **The executable.** `windows_subsystem = "windows"` in release builds (no console window; debug builds keep it for logs); its own resources, embedded by `build.rs` with `embed-resource` (already built by GPUI): the icon as resource 1 (which GPUI loads for its windows) and version information (product "Mellow", the workspace version). The manifest (no elevation, per-monitor DPI awareness v2, the Windows 10 id, common controls 6) is GPUI's: its `windows-manifest` feature links it into every binary depending on it, and a second one fails the link (`CVT1100: duplicate resource`). `mellow --version` prints the version and exits before anything starts, for the release job's check; from a terminal it attaches to the terminal's console to print there.
- **Release job** `desktop-windows` (on tags and on the pull requests and weekly runs that dry-run the release, ADR-0055): `cargo build --profile dist`, checks that the executable carries its version and the GUI subsystem, lays out the folder, compiles `mellow-desktop-X.Y.Z-x86_64-pc-windows-msvc-setup.exe`, then installs it silently, checks the files, the shortcut, the uninstall entry and `--version`, installs again over a running copy (a stand-in process named `mellow.exe` at the installed path), runs an `/UPDATE` install that waits for a copy quitting by itself, and uninstalls, checking that nothing listed is left. The installer is signed with minisign in `publish` like every asset, and listed in the expected assets.
- **Self-update** (ADR-0057 extended). Only the copy at `%LOCALAPPDATA%\Programs\Mellow\mellow.exe` (compared without case, component by component) in a writable folder updates itself; any other says it was not installed from a release package. A Mellow running elevated (as administrator) never updates itself: it would start, elevated, an installer that the user's unelevated programs can replace in the user's own folders, a way around UAC. It downloads `mellow-desktop-X.Y.Z-x86_64-pc-windows-msvc-setup.exe`, verifies its minisign signature before writing it, saves it as `mellow-setup.exe` in a staging directory under `%LOCALAPPDATA%\mellow\updates` (refusing a file that is not a Windows executable). That folder is not private on Windows: it inherits `%LOCALAPPDATA%`'s access list, so any program of the user (or an administrator) can write there. The app keeps the SHA-256 of the verified installer and, just before starting it, opens the file without write or delete sharing, checks the digest through that handle and keeps it open until the installer has started, so the file run is the file verified. It applies the update never during a call: at quit, it starts the installer with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE` and quits; "Restart to update" adds `/LAUNCH` and quits instead of GPUI's restart, and the installer opens the new version. A copy reinstalled by hand since staging (size and modification time differ) is not replaced. The staging directory stays while the installer runs from it and is removed at the next start. Running the installer reuses the logic every manual install runs (stop, replace, Start menu, uninstall entry with the new version), as Linux runs the package's own `install.sh`; the installer is the "small helper" that replaces an executable Windows will not let a running process overwrite.
- **SmartScreen and signing.** The installer and the app are not code-signed: Microsoft Defender SmartScreen shows "Windows protected your PC" for a downloaded installer without reputation; the README walks through "More info" then "Run anyway", after checking the `.minisig`. The app the installer writes carries no Mark of the Web and does not warn; a self-update downloads with the app's own client, so its installer carries none either and runs silently. **Where signing goes**: a step after the build signs `mellow.exe` before `cargo xtask windows-package` copies it, and `SignTool=` in the script (with `/S` given to `ISCC`) signs the installer and its uninstaller; the step stays in the protected `release` environment like the macOS identity (ADR-0055). A comment marks both places.

## Consequences
- A friend downloads one file, clicks through SmartScreen once and "Install" once; Mellow opens and updates itself from then on.
- One more release build per tag (about as long as a desktop CI build on Windows, with fat LTO), and Inno Setup to bump by hand (URL and digest).
- The update path closes a running Mellow by force after 60 seconds if it does not quit by itself, and a manual install closes it at once: unsent drafts are already saved to disk (wave 4); a call in progress ends.
- No rollback if the new version does not start, as on macOS and Linux (ADR-0057); the user reinstalls by hand.
- A Mellow started inside a job object that kills its children when it ends (some terminals) would take the update's installer down with it; started from the Start menu it is not.
- Until there is a certificate, every new release meets SmartScreen again when downloaded by hand (reputation follows the file's hash without a certificate); self-updates do not.

## Alternatives
The table above. Also: **MSIX outside the store** (sideloading) needs a trusted signing certificate, so it waits for one; it would bring clean updates through App Installer and package identity for notifications. **A self-written installer in Rust** (a Velopack-like single screen) would be ours to secure, sign and maintain for one screen Inno Setup already draws.
